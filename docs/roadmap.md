# 路线图

架构见 `docs/architecture.md`，选型依据见 `docs/proposal-wsl-linux-desktop.md`。原生 Windows CEF/WFP 路线（P0/P1）的计划与记录在 `docs/archive/roadmap-windows-native.md`。

## 可复用部分

- **中心与节点**（`server/`）：认证、节点授权、个人文件 API、隧道租约（[租约协议 v2](lease-protocol-v2.md)）。
- **Rust 核心**（`crates/orangespace-core`、`crates/orangespace-https`）：绑定与代次模型、文件任务归属、TUIC 配置生成、应用私有 HTTPS。
- **客户端**（`apps/windows-client`）：中心登录、授权节点、沙盒列表与绑定、节点文件客户端（`file_transfer`）、DPAPI 凭据。节点会话与租约的 C++ 库（`node_session`、`platform_session`）已迁到客户端，直接链接 `orangespace-https`。
- **分支 `feat/linux-desktop-sandboxes`**：
  - 每沙盒网关（`linux-desktop/network/gateway.py`），其真实内核回归已在 WSL2 上通过；
  - 桌面镜像与生命周期（`linux-desktop/guest/`）。

  其中的 QEMU/WHPX 底座、宿主桥与 Python 管理器已在 L3 收尾时删除，帧协议改为 `linux-desktop/wsl/wire.py`。

### 桌面断线重连（2026-11-21）

Debian 13 不收录 Xpra，改用 Debian 自带的 TigerVNC：

测试虚拟机实测，以下情况中 A、B 两个桌面的容器和 Chromium 进程都不变：
- 查看器被强杀后，3 秒内自动重连；
- 关窗后状态为 `window: closed`，桌面继续运行，再次 `start` 打开原桌面；
- 强制 WSLg 合成器崩溃后，合成器自行重启，两个窗口自动回来；
- 出口仍分别为新加坡、香港节点。

根文件系统改用 TigerVNC 后重新构建：321 个包，424 MB，多出的主要是 TigerVNC 服务端脚本依赖的 Perl。L5 验收时以当前代码构建的根文件系统从全新导入，桌面与出口检查通过（见 L5）。

**顺带修正**：一次打开时沙盒 B 的网关没接上，之后没能复现。为此做了两处修改：
- 网关等待 TUN 网卡改为按时间计（15 秒），原来按循环次数计，机器负载高时可能误判；

### 租约续期（进行中，2026-11-21）

节点改为不建库：账户、授权、节点登记全部以中心为准，节点只在内存里保存会话与租约。

- **节点**：`ORANGESPACE_NODE_STATE=memory`，进程内 SQLite，重启即清空。首次换票时按中心票据建本地身份与隧道授权，本地密码登录关闭。`linux-desktop/node/install-api` 安装（无 MySQL），`enroll-node` 用中心一次性令牌登记（令牌经管道直传，不显示、不落盘）。
- **中心**：
  - 运维命令 `orangespace-control-admin create-user / enroll-node / activate-node / grant / list-nodes`，与控制台同一把锁、同样写审计；
  - 首次授权自动建立用户与节点的身份映射；
  - 防重放（迁移 0007）：每个（节点、用户、沙盒）只认最新代次的隧道。用过的 tunnel_id 或不高于已记录的代次一律拒绝，节点重启后旧隧道无法复活。
- **客体**：网关新增租约模式。租约文件放在 tmpfs，只有 root 可读；每次续期在一个 nft 事务里把许可换成新的限时元素（最长 30 秒，扣 0.5 秒余量）。不再需要常驻 supervise 进程。desktop 与代理新增 `lease` / `renew` 操作，凭据只走代理的 stdin。
- **客户端**：`orangespace-sandbox <session.json>`（验收用前端；L4 起与窗口共用 `sandbox_engine`）。
  - 登录中心后，每个沙盒单独换取节点会话、创建隧道并交给客体，每 10 秒续租一次；
  - 续租被拒时用更高代次新建隧道，401 时重新换票；
  - 正常退出时撤销隧道、关闭桌面；进程被杀时续租停止，许可在租约剩余寿命内自动过期。
  - 信任文件放在 `C:\Program Files\OrangeSpace\trust`：所在目录与文件都须关闭继承，只有 SYSTEM 和 Administrators 可写。`C:\ProgramData` 普通用户可改属性，工具拒绝使用。

### 中心会话续期（2026-11-22）

### 暂停恢复与时钟偏差（2026-11-22）

测试虚拟机不支持任何睡眠状态（`powercfg /a`：虚拟机监控程序不支持 S1–S3、休眠和 S0 低电量待机），所以用宿主的 `virsh suspend` 把整台虚拟机暂停 65 分钟来近似休眠，跨过访问凭据的 1 小时寿命。

### 记住登录（2026-11-22）

登录界面加“记住登录”（默认勾选）。保存的是中心会话的**续期信息**（用户、会话、epoch、硬截止和一次性刷新凭据，`Session::export_renewal`），不保存密码和访问凭据；用已有的当前用户 DPAPI 存储（`platform_session::CredentialStore`：受保护目录、ACL 校验、待删除事务）。

- 刷新凭据只能用一次，所以窗口的 `Centre` 每次刷新后立即保存新的；启动时 `CredentialStore::load` 用它换新会话（`Session::resume`，中心必须回答同一用户、会话、epoch 与硬截止），返回前先保存换出的新凭据。
- 中心拒绝（401/403：已退出登录、改密码、停用账号、刷新凭据过期或被重放）或保存的内容无效时删除并回到登录界面；网络故障或其他 HTTP 状态时保留（`SavedSignInKept`），提示稍后再试或输入密码。
- 关闭窗口保留保存的登录，中心会话不撤销；**退出登录**撤销中心会话并删除保存的登录。用密码登录先删除旧的再按勾选保存。

## L5 安装与升级

- **安装器**：
  - 检测最低系统版本（Windows 11 22H2+ x64、Windows 10 22H2 x64）和硬件虚拟化；

### 实现（2026-11-21）

安装包用 Inno Setup 6.7，构建与行为见 [deploy/windows](../deploy/windows/README.md)。

- **安装包**：
  - 检查 Windows 10 22H2（19045）及以上的 x64 和硬件虚拟化；`wsl --version` 不可用时运行 `wsl --install --no-distribution` 并要求重启；
  - 文件只装到 `Program Files\OrangeSpace`，属主 Administrators，普通用户只读，`trust` 有自己的、不继承的 ACL；
  - 客户端正在运行时拒绝安装或卸载。
- **发行版**：
  - 由客户端在每个 Windows 账号首次运行时按 `system\release.json` 导入（WSL 发行版属于单个账号）。
  - 升级时客户端经新增的 `wsl/system` 导出沙盒数据到 `%LOCALAPPDATA%\OrangeSpace\upgrade`，记下摘要与沙盒数，然后注销、导入新发行版、放回数据、载入新镜像，核对版本号、镜像和沙盒数后才删除保存的数据。
  - 任何一步中断，下次启动先放回保存的数据。
- **卸载**：默认保留数据。选择删除时执行 `OrangeSpace.exe --remove-all-data`，登录界面也有同一操作“删除本机全部数据…”。
- **随附清单**：`licenses` 文件夹附：

  - 基础镜像摘要；
  - Rust 库许可（`scripts/rust_notices.py`）；
  - sing-box 与 seccomp 配置的来源和源码获取方式（`SOURCES.md`）。
- **客户端**：静态链接 C/C++ 运行库，不需要 VC++ 运行库；单实例。

# 路线图

架构见 `docs/architecture.md`，选型依据见 `docs/proposal-wsl-linux-desktop.md`。原生 Windows CEF/WFP 路线（P0/P1）的计划与记录在 `docs/archive/roadmap-windows-native.md`。

## 可复用部分

- **中心与节点**（`server/`）：认证、节点授权、个人文件 API、隧道租约（[租约协议 v2](lease-protocol-v2.md)）。
- **Rust 核心**（`crates/orangespace-core`、`crates/orangespace-https`）：绑定与代次模型、文件任务归属、TUIC 配置生成、应用私有 HTTPS。
- **客户端**（`apps/windows-client`）：中心登录、授权节点、沙盒列表与绑定、节点文件客户端（`file_transfer`）、DPAPI 凭据。节点会话与租约的 C++ 库（`node_session`、`platform_session`）已迁到客户端，直接链接 `orangespace-https`。
- **分支 `feat/linux-desktop-sandboxes`**：
  - 每沙盒网关（`linux-desktop/network/gateway.py`），其真实内核回归已在 WSL2 上通过；
  - 桌面镜像与生命周期（`linux-desktop/guest/`）。

  其中的 QEMU/WHPX 底座、宿主桥与 Python 管理器已在 L3 收尾时删除，帧协议改为 `linux-desktop/wsl/wire.py`。

### 租约续期（进行中，2026-11-21）

节点改为不建库：账户、授权、节点登记全部以中心为准，节点只在内存里保存会话与租约。

- **节点**：`ORANGESPACE_NODE_STATE=memory`，进程内 SQLite，重启即清空。首次换票时按中心票据建本地身份与隧道授权，本地密码登录关闭。`linux-desktop/node/install-api` 安装（无 MySQL），`enroll-node` 用中心一次性令牌登记（令牌经管道直传，不显示、不落盘）。
- **中心**：
  - 运维命令 `orangespace-control-admin create-user / enroll-node / activate-node / grant / list-nodes`，与控制台同一把锁、同样写审计；
  - 首次授权自动建立用户与节点的身份映射；
  - 防重放（迁移 0007）：每个（节点、用户、沙盒）只认最新代次的隧道。用过的 tunnel_id 或不高于已记录的代次一律拒绝，节点重启后旧隧道无法复活。
- **客体**：网关新增租约模式。租约文件放在 tmpfs，只有 root 可读；每次续期在一个 nft 事务里把许可换成新的限时元素（最长 30 秒，扣 0.5 秒余量）。不再需要常驻 supervise 进程。desktop 与代理新增 `lease` / `renew` 操作，凭据只走代理的 stdin。
- **客户端**：`orangespace-sandbox <session.json>`（验收用前端；L4 起与窗口共用 `sandbox_engine`）。
  - 登录中心后，每个沙盒单独换取节点会话、创建隧道并交给客体，每 10 秒续租一次；
  - 续租被拒时用更高代次新建隧道，401 时重新换票；
  - 正常退出时撤销隧道、关闭桌面；进程被杀时续租停止，许可在租约剩余寿命内自动过期。
  - 信任文件放在 `C:\Program Files\OrangeSpace\trust`：所在目录与文件都须关闭继承，只有 SYSTEM 和 Administrators 可写。`C:\ProgramData` 普通用户可改属性，工具拒绝使用。

### 多沙盒并发（2026-11-21）

三个沙盒同时运行：“香港 A”“香港 C”在香港节点（同一节点、各自的隧道），“新加坡 B”在新加坡节点。验收中发现并修复两个问题：
- **网关启动竞态**：网关只等到 `ostun0` 出现就加路由，而 sing-box 先建接口、稍后才启用它；接口还没启用时加路由失败（`Device for nexthop is not up`），网关随即拆除，桌面一直离线。三个沙盒同时启动时 B 就这样失败了。在发行版里单独实测，8 次中 2 次接口出现时尚未启用。改为等接口启用；新增行为测试（接口先未启用、后启用；始终不启用），旧代码两项都失败。
- **离线不自愈**：网关没起来或隧道进程退出后，租约照常续期，客户端从不重建。现在桌面在运行、租约有效而网关连续 3 次（约 30 秒）报告离线时换新隧道，客体随新租约重建网关；仍不通时等待加倍，最多约 5 分钟一次（`OfflineWatch`，有单元测试）。

### 记住登录（暂缓）

客户端已有当前用户 DPAPI 保存中心会话的存储（`platform_session::CredentialStore`，受保护目录、ACL 校验、退出时的待删除事务），但窗口还没有接入。原因是中心会话固定 1 小时（`session_ttl_seconds`）且没有续期接口：存下来的会话一小时后就失效。同一限制也意味着登录一小时后不能再打开新沙盒（已在运行的沙盒靠 8 小时的节点会话继续），需要退出重登。

要做时的方案：中心在登录时另发一份可轮换的刷新凭据（例如 30 天；每次使用换新，旧凭据被重放即作废整组；改密码、停用账号、退出登录都作废），客户端用 DPAPI 保存，并在运行中自动续中心会话。这需要改服务端、加数据库迁移并重新部署中心。

# 路线图

架构见 `docs/architecture.md`，选型依据见 `docs/proposal-wsl-linux-desktop.md`。原生 Windows CEF/WFP 路线（P0/P1）的计划与记录在 `docs/archive/roadmap-windows-native.md`。

## 可复用部分

- **中心与节点**（`server/`）：认证、节点授权、个人文件 API、隧道租约（[租约协议 v2](lease-protocol-v2.md)）。
- **Rust 核心**（`crates/orangespace-core`、`crates/orangespace-https`）：绑定与代次模型、文件任务归属、TUIC 配置生成、应用私有 HTTPS。
- **客户端**（`apps/windows-client`）：中心登录、授权节点、沙盒列表与绑定、节点文件面板、DPAPI 凭据。节点会话与租约的 C++ 库（`node_session`、`platform_session`）目前由服务和客户端共用，迁到客户端直接使用。
- **分支 `feat/linux-desktop-sandboxes`**：
  - 每沙盒网关（`linux-desktop/network/gateway.py`），其真实内核回归已在 WSL2 上通过；
  - 桌面镜像与生命周期（`linux-desktop/guest/`）。

  其中的 QEMU/WHPX 底座、宿主桥与 Python 管理器已在 L3 收尾时删除，帧协议改为 `linux-desktop/wsl/wire.py`。

## 退役

`apps/browserhost`、`apps/windows-service`（含 `sandbox/` WFP 库、原型服务与 OSP 协议）、`apps/windows-client` 中的浏览器嵌入与 CEF 打包、`tools/sandbox-devlaunch`、`drivers/wfp-prototype`。

退役前先把 `p0-consolidation` 上的原生方案完整提交保存，之后从主线删除，代码可在 git 历史中查到。退役时连同只服务于它们的测试和构建脚本一起删除，不保留无法运行的代码。

### 桌面断线重连（2026-11-21）

Debian 13 不收录 Xpra，改用 Debian 自带的 TigerVNC：

- **虚拟显示**：每个沙盒一个常驻 Xvnc，容器连在它上面。它以本沙盒专用账户运行，没有网络，看不到 WSLg 和 `/mnt`，不开 TCP。
- **查看器**：Windows 窗口是 vncviewer，经私有 Unix socket 连到虚拟显示，容器看不到这个 socket。
- **剪贴板**：两端都关闭。

测试虚拟机实测，以下情况中 A、B 两个桌面的容器和 Chromium 进程都不变：
- 查看器被强杀后，3 秒内自动重连；
- 关窗后状态为 `window: closed`，桌面继续运行，再次 `start` 打开原桌面；
- 强制 WSLg 合成器崩溃后，合成器自行重启，两个窗口自动回来；
- 出口仍分别为新加坡、香港节点。

根文件系统改用 TigerVNC 后重新构建：321 个包，424 MB，多出的主要是 TigerVNC 服务端脚本依赖的 Perl。尚未从全新导入重新验收。

**顺带修正**：一次打开时沙盒 B 的网关没接上，之后没能复现。为此做了两处修改：
- 网关等待 TUN 网卡改为按时间计（15 秒），原来按循环次数计，机器负载高时可能误判；
- desktop 把网关失败的原因写入发行版 journal（标识 `orangespace-desktop`），回复仍只给出笼统错误。

网关回归（`network/smoke.py`）在 WSL2 内核上复跑通过，这只证明 Linux 侧。

### 租约续期（进行中，2026-11-21）

节点改为不建库：账户、授权、节点登记全部以中心为准，节点只在内存里保存会话与租约。

- **节点**：`ORANGESPACE_NODE_STATE=memory`，进程内 SQLite，重启即清空。首次换票时按中心票据建本地身份与隧道授权，本地密码登录关闭。`linux-desktop/node/install-api` 安装（无 MySQL），`enroll-node` 用中心一次性令牌登记（令牌经管道直传，不显示、不落盘）。
- **中心**：
  - 运维命令 `orangespace-control-admin create-user / enroll-node / activate-node / grant / list-nodes`，与控制台同一把锁、同样写审计；
  - 首次授权自动建立用户与节点的身份映射；
  - 防重放（迁移 0007）：每个（节点、用户、沙盒）只认最新代次的隧道。用过的 tunnel_id 或不高于已记录的代次一律拒绝，节点重启后旧隧道无法复活。
- **客体**：网关新增租约模式。租约文件放在 tmpfs，只有 root 可读；每次续期在一个 nft 事务里把许可换成新的限时元素（最长 30 秒，扣 0.5 秒余量）。不再需要常驻 supervise 进程。desktop 与代理新增 `lease` / `renew` 操作，凭据只走代理的 stdin。
- **客户端**：`orangespace-sandbox <session.json>`（验收用前端，产品界面在 L4）。
  - 登录中心后，每个沙盒单独换取节点会话、创建隧道并交给客体，每 10 秒续租一次；
  - 续租被拒时用更高代次新建隧道，401 时重新换票；
  - 正常退出时撤销隧道、关闭桌面；进程被杀时续租停止，许可在租约剩余寿命内自动过期。
  - 信任文件放在 `C:\Program Files\OrangeSpace\trust`：所在目录与文件都须关闭继承，只有 SYSTEM 和 Administrators 可写。`C:\ProgramData` 普通用户可改属性，工具拒绝使用。

- 网关回归 `network/smoke.py` 在 WSL2 内核上通过，新增“租约续期与失效”阶段：每 2 秒续期一次，错误 tunnel 的续期被拒，停止续期后许可按时失效。这只证明 Linux 侧。
- 客体单元测试（desktop 20、agent 11、gateway 3）在 OrangeSpace 发行版内通过。
- 中心已在管理服务器上升级到迁移 0007，数据保留；香港节点按新流程安装、登记、激活，外网可达 8443。

- **只剩租约一条路**：网关删除静态节点配置（`configure`、常驻 supervise 进程、`local-persistent` 与 `ttl_seconds`），没有有效租约的沙盒保持离线。客户端工具 `orangespace-wsl` 去掉 `configure`。

从干净源码重新构建根文件系统（321 个包，424 MB，修订 `9200f0f+l3-cleanup`），在测试机上备份旧发行版后注销、全新导入：

- 冻结客户端：最后一次续租后约 29 秒许可由内核删除，E 完全断网（DNS 也失败），没有回退路径；恢复后两个沙盒都用更高代次新建隧道，出口回到各自节点。

两台节点上第一步留下的静态 TUIC 服务（UDP 443）已停用并删除，包括其证书、凭据和服务账户；租约服务不受影响，两个沙盒的出口不变。云安全组可以关闭 UDP 443。

### 切换节点与旧凭据重放（2026-11-21）

沙盒 E 从香港改绑新加坡（验收工具正常退出，修改绑定后重新启动）：
- 退出时隧道被撤销、桌面关闭；香港节点上没有残留的隧道进程，租约端口无监听。
- 用 E 在香港的旧租约凭据（TUIC uuid 与密码）从发行版直接连香港节点：凭据有效时能出网（对照），撤销后与切换后都无法出网。
- 客体用旧的香港 tunnel_id 续许可被拒。
- 切换后 E 的 HOME 保留（切换前写入的文件仍在），`egress-check` 全部通过，所有服务看到的都是新加坡 IP。
- E、F 同在新加坡节点时，各有自己的隧道、TUIC 凭据和端口（20000、20001），不共用。
- 发现桌面停止后过期的租约文件仍留在 `/run/orangespace/leases/`（root 0600，节点上已撤销）。已改为 `desktop stop` 一并删除；正常退出与强杀客户端两种情况下实测租约目录都被清空。


- 每个沙盒接入分支网关，先用静态节点配置跑通（已完成，静态路径已在 L3 收尾时删除）。
- 再改为由客户端创建、续租节点租约，代理据此续期内核限时许可；续租停止后许可自动过期。
- 新增 Linux 侧出口检查工具，相当于原生方案的 `orangespace-netcheck`，验证真实投递：TCP、UDP、DNS、IPv6、跨沙盒、宿主与内网地址。
- **验收**（用真实节点）：
  - Windows 物理网卡抓包，只见到发往两个节点端点的 UDP；
  - IP、DNS、WebRTC、QUIC 泄漏测试页分别显示各自节点的出口；
  - 断开节点 A，A 离线、B 不受影响；
  - 结束客户端进程，许可在租约剩余寿命内失效；
  - 切换节点后，旧代次的凭据与许可无法复活。

- 多沙盒并发：每个沙盒有独立的容器、网关、租约和显示；单个沙盒异常只影响它自己。

## L5 安装与升级

- **安装器**：
  - 检测最低系统版本（Windows 11 22H2+ x64、Windows 10 22H2 x64）和硬件虚拟化；
  - 开启"虚拟机平台"和 WSL，按需提示重启；
  - 安装 WSL 并导入发行版。
- **升级**：替换系统部分，保留用户数据。
- **卸载**：默认保留用户数据，另行提供"删除全部数据"。
- **分发清单**：附软件包清单和源码获取方式。
- **验收**：在全新机器上安装、升级、卸载各一遍。

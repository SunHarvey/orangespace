# Windows 客户端 v2：已确认界面与证据边界

设计依据：`approved-client-ui-v2`，2026-11-01 确认，替代旧管理器界面方向。
这是原有 C++20 客户端的视图和必要接口衔接，不是新的技术栈，也不改变 RDS、Service、TLS 信任和浏览器联网门禁。

## 四个界面

- 登录：居中登录卡片、账号、密码、记住登录、必要提示。安装脚本把管理员保护的 `platform.json` 和 `nodes.json` 放到程序旁；客户端按自身程序位置加载，不使用当前工作目录或用户输入的配置路径来建立信任。
- 授权节点：登录后自动读取完整真实授权列表，以卡片展示。节点名称取服务返回；没有地区、运行健康元数据时不编造位置或“在线”。
- 沙盒工作区：外层标签代表实际沙盒 UUID。默认打开恢复同节点已有沙盒；显式新增才增加独立沙盒。关闭停止运行资源、保留 SQLite/Profile；菜单删除需确认，只删除该沙盒本机数据。
- 个人文件：内容区内的当前节点个人文件目录树、文件列表、路径、筛选、上传、下载、新建目录和传输任务。没有服务端修改时间时显示空值。不是浏览器网页文件桥。

## 身份、文件与生命周期

登录来源、HTTPS 和受保护配置校验继续生效。记住登录使用既有用户范围 DPAPI。注销停止授权运行资源并清除对应凭据，不清沙盒数据；旧异步结果不能恢复身份。

同一 SDK Session 不允许并发修改；文件线程必须使用由界面所属身份捕获的凭据快照和独立 SDK 实例，不能在全局当前节点上取目标。每个文件任务从创建起固定用户、沙盒、节点和目录；切换标签只影响所见工作区，不修改任务目标。

上传/下载流式处理，不将整个文件读入内存。服务端确认原子提交后才能显示上传完成。下载先创建自身独占临时文件，成功后以不覆盖方式发布；取消/失败不能删除已有本机文件。不能因为浏览器被门禁而把文件 API 界面停留在示例数据。

浏览器后退、前进、刷新和地址入口仅能作用于当前沙盒真实浏览会话；在系统网络管控尚未通过时保持不可联网，内容区明确提示。不启动普通浏览器或添加绕过参数。

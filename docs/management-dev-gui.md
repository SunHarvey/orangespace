# Windows 客户端 v2：真实 GUI 验收与使用步骤

以 2026-11-01 确认的 `approved-client-ui-v2` 四张图和 [v2 界面契约](client-ui-v2.md) 为准，替代旧版配置路径、工程表格和逐项绑定操作。源码策略测试、CMake/CI、诊断 CLI 和进程创建不能代替实际窗口验收；没有截图和逐步证据的项目保持未验收。WFP/DNS、完整浏览器和网页文件桥仍不得提前开放。

## 准备

1. 使用 Windows 11 x64 普通用户已连接并解锁的交互桌面，不以管理员运行客户端。
2. 管理员用随包 `Service.ps1` 安装到独立、受保护 Program Files 目录，预置真实 `platform.json`、`nodes.json` 和合适状态账本。客户端按自身程序路径自动读取，不要求普通用户填写配置路径。没有默认账号或可工作的示例配置；不得用 fresh-only 账本覆盖既有世代/身份。
3. 用 `Start.ps1 -Leaf 实际安装目录的leaf` 或打开准确安装目录的 `OrangeSpace.exe`。脚本创建进程不代表 GUI 已验收。测试机已有 Foundation 时保留安装现场，不直接覆盖或重新安装。
4. 中心和 Node 保持正常 HTTPS 证书与名称验证，开发 CA 只通过受保护配置供应用使用；不改系统 Trust、不忽略 TLS 错误。

## 五组实际窗口验收

### 1. 登录与授权节点

仅在窗口输入中心账号和密码，按需选择“记住登录”。登录后自动显示真实获授权节点卡片。没有地区/健康字段时不编造备注或在线状态。身份来自认证回复；确认普通用户没有后台授权编辑入口。

### 2. 两个独立沙盒标签

点击一个节点的“打开沙盒”，后台自动完成工作区读取、默认沙盒创建或恢复、绑定、Service 独立授权及隧道建立。重复点击不增加重复 helper 或默认沙盒。

使用“＋”选择另一个授权节点或明确新开同节点独立沙盒。切换标签只切换视图，不改其他标签连接。分别关闭并重新打开，核对中心用户、真实沙盒 UUID、原节点和本机 Profile 归属，不以同名新建代替恢复。

删除位于菜单中且需确认，仅清理该沙盒本机数据。Linux 共享个人区、另一沙盒和其他用户的数据不能删除。当前服务观测、历史建立探测和持续业务流分别记证；不能为通过测试延长租约或把历史证明显示成持续联网。

### 3. 目录、上传、下载与内容核对

进入当前标签的“文件”，显示该节点该账号的真实个人目录。通过目录树、列表或路径操作进入目录，新建独立验收目录；选择或拖入一个已知内容的本机文件。

上传任务在服务端确认提交后才完成；重名应提示冲突，不静默覆盖。选中远端文件保存到用户选择的全新本机路径，核对完整字节或 SHA-256。失败或取消只能清理自己独占的临时文件，不能误删或覆盖已有文件。没有可靠修改时间时显示空值，不编造时间。

这是独立 HTTPS 文件 API 的管理界面，不代表网页 POST/blob/认证下载桥已完成。

### 4. 实际传输、取消和跨标签归属

使用足以观察任务状态的真实文件，记录方向、字节、已知或未知总量、状态和取消。传输期间切换另一标签；任务必须仍固定创建时的用户、沙盒、节点和目录。关闭标签保留任务归属，不删除远端个人区。

取消与服务端原子提交发生竞争时，不能承诺已提交的远端文件回滚；应检查真实远端结果，禁止伪造成功或偷偷删除远端文件。下载中止不得出现被当成完整下载的最终文件。

验证同账号同节点共享、不同账号拒绝及不同节点不自动同步；使用现有开发环境，不重新搭建一套无关验收框架。

### 5. 记住、注销与重新打开

勾选记住登录时使用用户范围 DPAPI，不保存原密码；正常关闭后重新打开自动在线验证恢复，并恢复正确本机沙盒归属。未勾选不留下可供重开的持久登录。

注销先失效身份和界面，取消文件任务、停止授权资源并删除对应持久凭据。文件取消等待期间界面应保持响应，不允许新身份提前复用旧任务；迟到响应不能恢复旧登录。清理或服务器注销未知时如实显示，不伪称远端全部撤销。

再次打开应要求登录；原 SQLite/Profile 和其他沙盒仍保留。密码、令牌和真实配置不得进入命令行、环境、日志、截图或程序包。

## 拓扑与证据

两个现有开发 Node 同机共享物理出口，身份、端口和数据目录独立；不是两个独立物理出口。归属以节点身份、API header 和完整 Service binding 核对，不能只比较公网 IP。

每组记录本次准确来源提交、程序哈希、实际安装路径、窗口截图或短操作录像、结果及未验收项。设计图、旧候选截图、旧 Service 运行结果、交叉编译和 CI 均不能单独替代新包 GUI 验收。

RDS 的实际引擎/版本、endpoint/port、专用库权限、TLS CA 和正式管理服务器资料仍由用户提供。开发隔离 MySQL 不冒充用户 RDS，也不阻塞不依赖这些资料的客户端工作。
